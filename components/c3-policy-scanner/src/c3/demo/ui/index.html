What you are looking at

Every answer from the AI assistant is checked against the hospital's own policy before a clinician sees it. A violation is withheld, and an administrator can see exactly which rule it broke and the words of that rule.

  1. Privacy check. Identifiers in the question are replaced by placeholders. Here a simple stand-in does this.
  2. Assistant answer. In the demo you type the answer, or connect a real language model.
  3. Policy check. The part being demonstrated. It finds the relevant rules, a small trained model decides, and every citation is checked against the real rule text.
  4. Behaviour check. Receives one event per check. A stand-in shows the closed loop.

Clinician view shows a safe message and a reference number only. Admin view shows the rule, the quote and the model's confidence. Use the switch at the top right.

Honest limits: the model shown here was trained on hand-written examples, so treat verdicts as a demonstration, not as a clearance. It sometimes flags a safe answer or cites a neighbouring rule. The thumbs under each admin result save your judgement so real labelled data can be collected.

Progress: about 50% complete

This is the first progress evaluation. Two requirements are finished and demonstrated here; the rest of the component is planned for the next evaluation.

Done and shown in this demo

  • FR1, clause parsing with stable IDs. A policy PDF or Markdown file becomes clauses with IDs that stay the same when the document is revised. Broken files are rejected with a reason.
  • FR2, live re-indexing of changed clauses only. Editing or replacing a policy embeds only what changed and swaps in the new version with no restart. Open the Policies tab to try it.
  • The policy check itself, shown in the Chat tab: relevant rules are found, a small trained model decides, citations are checked against the real rule text, and a failed check withholds the answer.

Yet to complete

  • Accurate rule citations. The verdict is usually right, but the scanner sometimes cites a neighbouring rule (for example 4.2 where 4.1 was broken). Sharper attribution to the exact clause is still to do.
  • Better accuracy. The model over-flags and misses some paraphrased violations. Threshold tuning, a larger model and human-reviewed labels are still to do.
  • Real connections. The privacy, intent and behaviour steps here are stand-ins. Integration with the real gateway and the other components is not done.
  • Hardening. Prompt-injection tests, Sinhala and Tamil answers, personal-data detection with Presidio, faster int8 serving and memory checks with all components running.
  • Evaluation. Held-out unseen-policy sets, the remaining comparison baselines, and the system-level tests with the other components.
  • Packaging. The container image is written but not built or tested.
