## 2. Integrated Compose (`infra/compose/docker-compose.yml`)

| Service | Image / build | Ports | Volumes | Depends on |
|---|---|---|---|---|
| `web` | `apps/web/Dockerfile` (nginx static) | **80 (and 443) published** | n/a | gateway |
| `gateway` | `apps/gateway/Dockerfile` | internal 8000 | n/a | mongo, c1, c2, c3, c4 (healthy) |
| `c1` | `components/c1-privacy-assistant/Dockerfile` | internal 8001 | `c1_db`, `c1_models:ro` | c4 |
| `c2` | `components/c2-intent-classifier/Dockerfile` | internal 8002 | `c2_db`, `c2_chroma`, `c2_models:ro` | c4 |
| `c3` | `components/c3-policy-scanner/Dockerfile` | internal 8003 | `c3_db`, `c3_chroma`, `c3_files`, `c3_models:ro` | c4 |
| `c4` | `components/c4-risk-profiler/Dockerfile` | internal 8004 | n/a | mongo |
| `mongo` | `mongo:7.0` (`mongo:4.4` if no AVX) | internal 27017 | `mongo_data`, `infra/mongo/init` | n/a |

- Build context for every Python service is the repo root, so its Dockerfile can copy `packages/mediguard-common` and `contracts/`.
- All services have healthchecks on `/health`.
- One network: `mediguard-internal`.
- The gateway reaches the LLM at `GW_LLM_API_URL` (tunnel at `host.docker.internal:18010`, `extra_hosts: host-gateway`).

## 3. Configuration and secrets

| File | Holds |
|---|---|
| `.env.example` (root) | Every variable the integrated Compose needs, with placeholders |
| `infra/env/*.env.example` | Per-service templates (copied to `*.env` on the host) |
| Real `.env` files | Only on machines; never in Git; shared via a password manager |

Service keys:
- one per service (`gateway`, `c1`, `c2`, `c3`, `c4`);
- generated by `infra/scripts/rotate_keys.sh`;
- given to each receiver through `MG_ACCEPTED_KEYS` (contracts §5).

Rotate them before integration and again before the final demo.

## 4. CI/CD (`.github/workflows/`)

| Workflow | Trigger | Steps |
|---|---|---|
| `ci-components.yml` | PR / push touching `components/**`, `packages/**`, `contracts/**` | Matrix over changed components: install, `ruff`, `pytest tests/unit tests/contract` |
| `ci-gateway.yml` | `apps/gateway/**`, `packages/**`, `contracts/**` | ruff, pytest (unit, contract, RBAC, pipeline with stubs) |
| `ci-web.yml` | `apps/web/**` | `pnpm install --frozen-lockfile`, lint, typecheck, build; Playwright on `main` |
| `contracts.yml` | `contracts/**` | `python contracts/validate.py` + every service's contract tests |
| `security.yml` | PR + weekly | `pip-audit`, `pnpm audit`, secret scan, Trivy on built images |
| `images.yml` | Tags `g3-*`, `g5-*`, `final` | Build and push images to GitHub Container Registry |

## 5. Branching and reviews

- `main` is protected: a pull request, green CI, and approval from the `CODEOWNERS` owner of each touched path.
- Branch names: `c1/<topic>`, `c2/<topic>`, `c3/<topic>`, `c4/<topic>`, `gw/<topic>`, `web/<topic>`, `infra/<topic>`, `docs/<topic>`.
- Commits follow Conventional Commits with scope: `feat(c3): ...`, `fix(gateway): ...`, `data(c2): ...`.
- **Contract changes** after G2 need a pull request labelled `contract-change`, approved by all four owners, plus a `contracts/VERSION` bump.
- Tags:
  - `contracts-v1.0.0` (G2)
  - `g3-mvp`
  - `cN-frozen-v1` (G4)
  - `g5-models`
  - `final`

## 7. Operations

| Task | How |
|---|---|
| Health | `curl http://<host>/api/health` (gateway reports C1 to C4, LLM, Mongo, active pipeline) |
| Logs | `docker compose logs -f <service>`; JSON lines without text |
| Backup | `infra/scripts/backup.sh`: Mongo dump (`c4`, `gateway`), SQLite volumes, C3 policy files, to a dated folder |
| Restore | `infra/scripts/restore.sh <folder>` |
| Demo day | `docs/runbooks/demo-day.md`: rotate keys, seed, upload policies, warm the LLM (`keep_alive`), run `make smoke` |
| Incident | `docs/runbooks/incident.md`: any component down means the product fails closed; check `/api/health`, restart the service, check the outbox drains |
